02 — System architecture

Three clients, one real-time backend

There is no custom server. The Android app does the AI work at the edge, Firebase stores and protects the data, and a Next.js dashboard gives each role its own scoped view. Every arrow below carries structured data only — never camera images.

1 Rider signs in (rider role only on Android) 2 Detection metadata, merged in a transaction 3 Push alerts & live-session updates 4 Web sign-in, role read from database 5 Real-time listeners & role-scoped writes

Design principles

  • Privacy first — frames and video stay on the device.
  • Offline first — every report hits the local outbox before the network.
  • Server-enforced roles — rules decide, not the UI. Self-registration is always a citizen.
  • Open maps — OpenStreetMap / OpenFreeMap, no API keys or billing.
  • Honest data — no invented positions, confidence or numbers.
Data stores at a glance
reports/one row per physical pothole: status, priority, assignee, deadline, total detections
detections/every single pass by every vehicle; append-only and private to the reporter
activity_logs/every status change with who, when and why; can never be edited
Room (phone)local outbox of pending reports, so nothing is lost without signal

03 — On-device AI pipeline

Ten steps from camera frame to a trusted report

Every frame is analysed on the phone. A detection becomes a report only after it survives temporal confirmation, confidence and duplicate gates, and a fresh GPS fix. The driver is warned instantly, even with no network.

Perception — steps 1–4 Decision — steps 5–8 Action — steps 9–10

Severity engine (deterministic)

areaRatio = (w × h) ÷ (640 × 640)

  • HIGH  ratio ≥ 0.08, or confidence ≥ 0.85 and ratio ≥ 0.04
  • MEDIUM  0.03 ≤ ratio < 0.08
  • LOW  ratio < 0.03
  • Heading-aware alerts: a pothole within 65° of travel direction is "ahead"; beyond 70° it has been passed.

Server-side duplicate merge

One pothole, many passes. Each pass is kept as an immutable row in detections/; the physical defect lives once in reports/.

Adaptive radius. A new detection merges into an existing one within clamp(GPS accuracy, 10 m, 25 m), found with a bounded latitude-band query.

Concurrency-safe. A Firebase transaction increments totalDetections, so two vehicles passing at once never overwrite each other.

04 — Report lifecycle

Nine audited stages, three accountable roles

A report moves down the swimlanes as each role acts on it. Security rules allow only the transitions shown, a contractor can never close its own job, and every change writes an append-only entry to activity_logs/.

One audit entry per transition

Written next to every status update in activity_logs/{reportId}. Rules make it append-only and require the writer to be the signed-in user, so the history of each pothole can be trusted.
